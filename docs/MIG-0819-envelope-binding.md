# Offline native output envelope qualifier

tools/blog_output_envelope_parity.py checks the saved artifact's outer native
projection only. OFF by default, read-only, no runtime caller and no generation,
model, publisher or provider. Every result is HOLD with enabled=false,
approved=false and publish_allowed=false.

~~~sh
python3 -I -B tools/blog_output_envelope_parity.py
python3 -I -B tools/blog_output_envelope_parity.py --offline \
  --artifact /explicit/synthetic/site-config.json
~~~

Default: exit 0, DISABLED, no artifact reads. Explicit offline: exit 0 for
MATCH/HOLD or exit 1 for REFUSED/HOLD. Reports contain fixed codes/booleans,
never paths, unknown field names, content or exception text. This CLI is not
an MCP tool and adds no MCP arguments.

## Native structural contract

The independently pinned City adapter writes exactly one artifact root key,
blog_posts, containing one dictionary. Its fixed outer post projection retains
only title, slug, intro, sections, citations, source_action_id and source_topic,
with the last two always added. Thus any other root/post field or missing
provenance key is inconsistent with this pinned serialized envelope.

Foreign saved operational fields such as approved, gatePass, enabled and
publication_enabled refuse, as do harmless-looking metadata fields the native
adapter drops and invented/case/hidden-Unicode field names. This is an allowlist,
not a guessed blacklist. Root keys and mandatory provenance KEY PRESENCE are
checked; field values/editorial/nested schemas are not.

This is the next distinct boundary after original-request identity. A saved
post with unchanged action/topic and injected approved=true still matches the
identity-only qualifier, but fails this envelope qualifier. Neither result is
publication authority. PR14's transfer/attempt/hash custody is not reimplemented.

The qualifier reuses the same bounded no-follow/single-link reader, strict JSON
scalar parser and final no-follow input-identity observation as the existing
qualifiers. A shared one-post shape helper and 2 MiB artifact cap replace the
previous request CLI's equivalent inline logic without changing its behavior.
No native producer, config, workflow, policy or live state changes.
